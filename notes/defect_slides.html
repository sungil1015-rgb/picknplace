02

공유 substrate — 같은 crop·backbone, 다른 layer 소유권

동일 crop·동일 backbone forward를 공유하되, 분류기와 결함 detector는 서로 다른 DINOv2 layer를 소비해 상보적이다

LAYER OWNERSHIP
분류기 = 최종 layer (semantic 카테고리)
detector = 중간 layer (국소 이상)
base 분류기 L12 detector L5–8
분류기 = CLS 전역 임베딩으로 '카테고리'
detector = 국소 patch로 '정상 표면 이탈'
미배선 fallback
설계상 backbone forward는 객체당 1회면 충분. 현재는 분류기가 중간 layer를 노출 안 해 detector가 자체 forward로 fallback.

crop 규격 동일: 정사각 bbox · padding 3% · bg gray127 mask-out · 224 리사이즈 · 14px patch → 16×16=256 token  ·  base 기준 ablation, L12 제외

03
분류기 · DINOv2 KNN

DINOv2 분류 로직 — CLS 임베딩 cosine KNN + unknown gating

임베딩

cls_weight·CLS + patch_mean_weight·patch_mean — 기본값 (1.0, 0.0)이라 기본은 CLS-only. patch-mean은 config가 켤 때만 기여.

layer

분류기는 last_hidden_state(최종 layer)만 사용 — output_hidden_states 미요청. 중간 layer 노출은 통합 시 추가할 부분.

unknown gating

min_class_score / min_similarity / min_vote_ratio / min_margin 4개의 OR — 하나라도 트립하면 unknown(id 5)으로 거른다.

정확성 주의

confidence(class_score)는 이웃 softmax 가중합 — 정규화 확률 아님. 클래스 합<1 가능. 'probability'로 부르면 오류.

margin = 승자 vs 차순위 클래스 mean-cosine 차이. top-k에 단일 클래스만 있으면 +inf.

라벨 매핑

뱅크 라벨 {1..5} → labels−1 shift 후 UNKNOWN=5 매핑 성립.

분류기 = 최종 layer / 결함 = 중간 layer (상보적) · class_index → DefectRegistry → 클래스별 detector · 출처 ALGORITHM_REPORT.md §2.2
