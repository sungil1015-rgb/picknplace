# 분류 + 불량탐지 로직 발표자 브리핑 — "왜 이렇게 설계했나"를 이해하고 답하기

> **이 문서의 목적**: 이 브리핑은 `ALGORITHM_REPORT.md`(정밀 스펙)를 읽고 발표를 맡은 사람이, 코드 디테일을 암기하지 않고도 "이 로직이 **왜 이렇게 생겼는지**"를 직관으로 이해하고 청중 질문에 흔들리지 않게 방어하도록 만드는 **학습용 브리핑**입니다. 비유는 이해를 돕되 수치·판정은 절대 왜곡하지 않습니다. 정확한 수치를 물으면 `ALGORITHM_REPORT.md`의 표(§6/§7)를 참조하세요.

---

## 이 문서 사용법

- **읽는 순서**: 위에서 아래로 한 번 정독하면 전체 직관이 잡히도록 배열했습니다(도입 → 큰 그림 → DINOv2/layer → 분류 → 전략 분기 → 세 detector → 오프라인 캘리브 → 정직한 한계 → Q&A 부록).
- **각 섹션 구성**: ① 한 줄 직관 → ② 왜 이렇게 설계했나 → ③ 메커니즘 → ④ "이렇게 답하세요" 박스 → ⑤ 정직성 노트.
- **암기할 것 vs 참조할 것**: **직관과 판정 규칙**(다수결 ≥2, normal-only, 물성·CV 분기)은 외우고, **정확한 수치**(τ, σ, layer별 AUROC 소수점)는 `ALGORITHM_REPORT.md` 표로 확인해 답하면 됩니다. 즉답 못 하는 건 약점이 아니고, **거짓 추측이 약점**입니다.
- **정직성이 방어의 핵심**: 미배선·`enabled:false`·layer staged·합성 도메인갭·단일 seed는 약점이 아니라 **"현재 검증 경계"**입니다. 먼저 인정하는 답이 신뢰를 만듭니다.

## 발표 흐름 가이드 (시간 배분 예시)

| 시간 | 다룰 것 | 핵심 메시지 |
|---|---|---|
| **5분 버전** | 핵심 한 줄 + 큰 그림 6단계 + 핵심 3종 자동응답 | "정상만 학습 → 분류 후 클래스별 검사 → 물성이 전략을 정한다" |
| **10분 버전** | 위 + DINOv2 layer 직관 + 세 detector 한 줄씩 + 정직한 한계 | "같은 backbone, 다른 깊이 / rigid=단일, deformable=다수결" |
| **20분 버전** | 전 섹션 + 오프라인 캘리브(LOO·합성·layer ablation) + Q&A 부록 전체 | "수치는 조건부(base·합성·LOO·단일seed), 실물 재검증이 다음 단계" |

## 핵심 한 줄 요약 (발표자가 먼저 외울 것)

> 빈피킹에서 **"이게 무엇인지(분류) 안 다음, 그 객체 표면에 흠이 있는지(결함)"**를 봅니다. 결함은 너무 드물고 종류가 무한해서 모을 수가 없으므로, **결함을 가르치지 않고 '정상이 어떻게 생겼는지'만 외워 두고 거기서 벗어나면 결함으로 보는** 방식 — 무결함(normal-only) 이상탐지 — 을 택했습니다. 전략은 **객체 물성과 정상 변동성(CV)**이 정하고, detector는 아직 메인 루프에 **미배선**(설계·오프라인 검증 단계)입니다.

## 1. 도입 — 왜 이 문제인가 & 무결함(normal-only) 이상탐지란

### 1.1 직관 먼저 — '정상 지문 도감'을 든 검사원

불량 유형을 하나하나 외운 검사원이 아니라, **정상품이 어떻게 생겼는지만 완벽히 외운** 검사원을 떠올리세요. 새 물건이 들어오면 도감(정상 패턴 모음) 어디에도 맞지 않을 때 "정상 아님 → 의심"이라고 외칩니다. 처음 보는 형태의 흠집이라도, 정상이 아니기만 하면 잡힙니다.

이게 합리적인 이유는 **데이터의 현실** 때문입니다.

- 결함 샘플은 **드물고**(생산 라인에서 불량은 소수), **종류가 사실상 무한**합니다(스크래치, 찢김, 눌림, 이물질, 한 번도 본 적 없는 변형…).
- "모든 불량 유형을 미리 모아서 학습"하는 접근은 결함 데이터를 모으는 것부터 막힙니다. 못 본 결함은 영원히 못 잡습니다.
- 반대로 **정상품은 얼마든지 있습니다.** 그래서 "정상만 모으면 된다"가 핵심 강점입니다. **결함 라벨이 단 한 장도 필요 없습니다.**

스팸 필터로 한 번 더: 세상 모든 스팸 유형을 미리 수집하는 대신, **'정상 메일이 어떻게 생겼는지'만 외워 두고** 거기서 크게 벗어난 메일을 의심하는 역발상과 같습니다.

### 1.2 메커니즘 — 구체적으로 무엇을 하나

**(a) 이상탐지(anomaly detection)란.** 정상의 분포를 학습하고, 새 입력이 그 정상 분포에서 **얼마나 벗어났는지**를 점수로 매겨, 점수가 임계(τ)를 넘으면 결함으로 판정합니다. "불량을 분류"하는 게 아니라 "정상에서의 이탈"을 잽니다.

**(b) normal-only 학습 = memory bank.** 정상 객체들의 표면 조각(patch) 특징을 모아 **memory bank**(정상 patch 도감)를 만듭니다. 테스트 객체의 각 patch에 대해 **bank 안에서 가장 가까운 정상 patch까지의 거리**를 재고, 그 거리가 멀면 "정상 어디에도 안 맞는다 → 결함"입니다. 학습에 들어가는 건 **정상 patch뿐**입니다. (이 거리 기반 판정이 PatchCore-lite의 핵심이며 §6에서 상세히 다룹니다.)

**(c) 왜 '분류 먼저, 그다음 결함'인가.** 파이프라인은 ① 분할 → ② **분류(이게 무엇인지)** → ③ **그 객체 표면의 결함 검사** 순서입니다. 분류를 먼저 하는 이유:

- 객체마다 **'정상'의 모습이 다릅니다.** 메탈케이스의 정상과 하리보(젤리)의 정상은 완전히 다른 도감이 필요합니다. 무엇인지 알아야 **그 클래스 전용 정상 도감**을 꺼낼 수 있습니다.
- 분류 결과(`class_index`)가 클래스 전용 detector로 객체를 라우팅합니다: rigid 객체(필통·메탈케이스)는 PatchCore, 잘 변형되는 하리보는 4신호 voting(cascade), 젤리껌(코드명 **mango**)은 fusion. 같은 캔디류라도 젤리껌은 정상 분포가 매우 타이트(CV 0.126, rigid급)해서 다른 전략으로 갑니다.
- 분류기와 결함 검사기는 **같은 crop·같은 DINOv2 backbone을 공유**합니다. 분류기는 **최종 layer의 의미(semantic) 특징**으로 '무엇인지'를, 결함 검사기는 **중간 layer의 국소 표면 특징**으로 '표면이 정상에서 벗어났는지'를 봅니다. 서로 다른 layer를 보기에 **상보적**입니다(그래서 결함 layer 분석에서 최종 layer는 제외). 한 번의 forward로 두 일을 나눠 맡는 효율적 구조입니다.

### 1.3 이렇게 답하세요

> **Q. 결함을 본 적도 없는데 어떻게 잡나요?**
> "결함을 외우는 게 아니라 **정상을 외웁니다.** 정상 patch 도감에서 가장 가까운 정상까지의 거리가 멀면 정상 어디에도 안 맞는다는 뜻이라 결함으로 봅니다. 그래서 처음 보는 유형의 흠집도 '정상 아님'으로 잡힙니다."

> **Q. 왜 분류와 결함탐지를 한 번에 안 하고 분류를 먼저 하나요?**
> "**객체마다 '정상'의 기준이 다르기 때문**입니다. 무엇인지 알아야 그 클래스 전용 정상 도감을 꺼내 검사할 수 있습니다. 게다가 backbone을 공유해 분류는 최종 layer(의미), 결함은 중간 layer(표면)로 일을 나눠 효율적입니다."

> **Q. 정상 데이터는 얼마나 필요한가요?**
> "**대략 클래스당 수백 개 객체** 수준입니다. 예로 젤리껌(mango) memory bank v2는 정상 309개 객체로 구성했습니다. 결함은 한 장도 필요 없고, 정상품만 모으면 됩니다."

### 1.4 정직성 노트

action 피드백과 `pick_n_place` 배선은 **설계 단계(미배선)**, 젤리껌(mango)은 `enabled:false`로 **실물 찢김 테스트 대기**, 클래스별 best layer는 분석으로 정했으나 운영 bank 재빌드는 **staged**(진행 중), 본 도입 수치는 base·합성결함·LOO·단일 seed 기준이라 **실물 재검증 대상**입니다. 핵심 아이디어(정상만 학습)는 견고하되, 구체 운영점은 검증 진행 중임을 솔직히 전달하세요.

## 2. 큰 그림 — 파이프라인 한 장으로 보기

### 2.1 공장 검수 라인 직관

컨베이어 위 물건이 흘러갈 때 라인은 세 사람이 순서대로 일합니다.

1. **분류기** — "이게 뭐지?" (하리보? 필통? 메탈케이스?)
2. **검수원** — "흠집 있나?" (결함 탐지)
3. **집게 로봇** — "집을까, 버릴까, 뒤로 미룰까?" (파지 우선순위 → suction)

핵심 질문 하나만 기억하면 됩니다: **왜 검수원(결함 탐지)을 분류기 바로 다음 칸에 두었나?** 답은 "검수원이 물건 종류를 알아야 그 품목의 검사기준표를 꺼낼 수 있어서"입니다. 메탈케이스 기준과 하리보 기준은 다르니까요.

> **정직하게 먼저 못 박고 갑니다**: 이 검수 기계는 "만들어서 라인 옆에 세워 뒀지만, 아직 컨베이어에 볼트로 끼우지는 않은" 상태입니다. 설계와 오프라인 검증은 끝났지만 `pick_n_place.py` 메인 루프에는 아직 배선되지 않았습니다. "지금 로봇에서 돌고 있나요?"라는 질문에는 "아직 미배선, 설계·검증 단계"라고 답하세요.

### 2.2 파이프라인 6단계 (`pick_n_place.run()`)

```
RGB-D + normal + ROI
   │
   ▼
① Mask2Former 세그멘테이션      → instance masks (객체 분리)
   │
   ▼
② mask 정제 + polygon           (가장 큰 연결성분 추출, polygon화)
   │
   ▼
③ DINOv2 KNN 분류               → class_index, similarity, …
   │
   ▼  ┌──────────────────────────────────────────────┐
   │  │ ★ 결함 탐지 삽입 지점 (설계됨, 현재 미배선)   │
   │  │   DefectRegistry.get(class_index)            │
   │  │     .score(rgb, mask, normal, dinov2_feats)  │
   │  │   → DefectResult(score, is_defect, votes…)   │
   │  └──────────────────────────────────────────────┘
   ▼
④ 파지 우선순위 scoring         (grasp priority)
   │
   ▼
⑤ suction point (최상위 우선순위 객체)
   │
   ▼
⑥ 정렬 + 반환  sort by (suction, priority, similarity, score)
```

- **① 세그멘테이션(Mask2Former)**: 빈(bin) 안 뒤섞인 물체를 인스턴스별 마스크로 떼어냅니다.
- **② mask 정제**: 마스크를 다듬어 polygon으로 만듭니다(crop 기준).
- **③ 분류(DINOv2 KNN)**: crop을 DINOv2에 통과시켜 최종 layer 전역 임베딩(기본 CLS-only)을 뽑고, reference bank와 cosine KNN으로 비교해 `class_index`를 정합니다. 동시에 unknown gating으로 "모르는 물건"을 걸러냅니다.
- **[결함]**: 분류 결과를 받아 그 클래스 전용 검사기로 표면 결함을 판정합니다(§6 상술).
- **④ 파지 우선순위 / ⑤ suction / ⑥ 정렬 반환**: 어느 객체를 먼저 집을지 정해 로봇에 넘깁니다.

### 2.3 왜 하필 "분류 직후"인가 — 세 가지 이유

**(1) `class_index`가 있어야 클래스별 detector를 고른다 (라우팅).** `DefectRegistry`가 `class_index`를 받아 전용 검사기로 보냅니다:

| idx | class(코드명) | detector | 비고 |
|---|---|---|---|
| 0 | 하리보 (haribo) | **cascade** (≥2/4 voting) | deformable |
| 1 | 젤리껌 (mango) | **fusion** (w=0.25) | `enabled:false` |
| 2 | 필통 (pencil_case) | **patchcore** (max) | rigid |
| 3 | 메탈케이스 (metal_case) | **patchcore** (max) | rigid |
| 4 | 물병 (bottle) | **제외** | 투명 plastic, 빛 투과로 mask 오염 |
| 5 | 언노운 (unknown) | **우회** | 분류기가 거름 |

분류 결과가 없으면 검수원이 어느 기준표를 꺼낼지 모릅니다. 그래서 분류가 선행이어야 합니다.

**(2) DINOv2 forward를 재사용한다 (연산 1회).** 분류기와 결함 탐지는 **같은 crop·같은 backbone**을 씁니다. 차이는 보는 layer입니다 — 분류기 = **최종 layer**(semantic), 결함 = **중간 layer**(국소 표면). 이상적 경로는 분류가 이미 돌린 forward의 중간 layer patch token을 캐시로 넘겨받아 **결함이 backbone을 다시 안 돌리는 것**(추가 forward 0회)입니다.

> 정직 보충: 현재 분류기는 `last_hidden_state`만 쓰고 중간 layer를 노출하지 않아, 통합 전까지는 결함이 자체 backbone을 lazy 로드해 직접 forward하는 fallback 경로로 동작합니다(정확하지만 연산 중복). "0-forward"는 설계된 이상 경로입니다.

**(3) 판정을 우선순위에 피드백한다 (루프 의도).** 설계 의도는 detector의 `action` 속성에 따라 `reject`(파지 제외) / `priority_down`(후순위 감점) / `report_only`(로깅만)로 동작합니다. 이 피드백이 ④·⑥에 반영되려면 결함 판정이 그보다 **앞**이어야 합니다.

> 정직 보충: 현재 활성 클래스의 `action`은 전부 `reject`로 지정돼 있으나 **이를 소비하는 코드는 아직 없습니다.** 정렬 key에도 `priority_scorer`에도 결함을 읽는 부분이 없어, "결함이면 안 집는다"는 아직 설계 의도일 뿐입니다.

### 2.4 이렇게 답하세요

> **Q. 이거 실제 로봇에 연결돼서 돌고 있나요?**
> "아직 미배선입니다. detector 서브시스템과 오프라인 검증은 끝났지만 `pick_n_place.py` 메인 루프에는 아직 연결하지 않았습니다. `src/defect`를 import하는 건 오프라인 `scripts`뿐입니다."

> **Q. 결함이 발견되면 로봇이 실제로 안 집나요?**
> "설계 의도는 `reject`(파지 제외)가 맞습니다. 다만 그 `action`을 읽어 우선순위에 반영하는 소비 코드는 아직 작성 전입니다. 정렬 key에 결함 플래그를 추가하는 형태가 자연스러운 통합 지점입니다."

> **Q. 분류가 틀리면 결함 탐지도 엉뚱한 기준으로 보는 거 아닌가요?**
> "맞습니다 — 오분류 시 잘못된 검사 전략·잘못된 memory bank로 판정합니다. 그래서 분류기에 unknown gating(min_score/sim/vote/margin OR)을 둬, 확신 없는 객체는 unknown으로 빼 결함 라우팅 입력에서 제외합니다. 분류 신뢰도가 결함 판정 신뢰도의 전제라는 점은 인정하고 가는 설계입니다."

## 3. DINOv2와 layer 직관 — 같은 backbone, 다른 깊이를 본다

### 3.1 한 문장 직관

> 신경망의 깊이는 **추상화 사다리**다. 아래 칸은 "실밥·긁힘" 같은 표면·질감을 보고, 위 칸은 "이건 메탈케이스"라는 **카테고리 개념**을 본다. 우리는 같은 backbone에서 **분류는 맨 위 칸**(무엇인지)을, **결함은 중간 칸**(국소 표면)을 읽는다. 한 번의 forward로 두 칸을 동시에 본다.

왜 칸을 나눠 읽나? **최종 layer는 "정상 메탈케이스"와 "긁힌 메탈케이스"를 같은 단어로 부른다.** 카테고리로 수렴해버리니 둘의 차이가 사라진다. 반대로 중간 layer는 아직 표면을 보고 있어서 긁힘이 정상 표면 분포 밖으로 **튄다**. 그래서 두 신호는 **상보적**이다 — 분류가 잘 쓰는 신호가 결함엔 죽고, 결함이 잘 쓰는 신호는 분류가 안 본다.

다른 비유: 한 장의 인물 사진을 **멀리서 보면(깊은 층)** "같은 사람"이고, **가까이 보면(중간 층)** 얼굴의 흉터가 보인다. 신원 판별은 멀리서, 흉터 탐지는 가까이서 — 같은 사진, 다른 거리.

### 3.2 DINOv2가 뭔가

- **DINOv2** = 라벨 없이(self-supervised) 학습된 ViT(Vision Transformer) 비전 백본. 우리는 이걸 **새로 학습시키지 않았다.** `facebook/dinov2-base`를 가져와 **freeze**한 채 feature만 뽑아 쓴다.
- 이미지를 **patch token**들로 표현한다. 입력 **224×224 → patch_size 14 → 한 변에 16개 → 16×16 = 256 patch token**. 각 patch는 그 자리 표면의 작은 벡터(base 차원 D=768 / large 1024).
- **CLS token**(token0) = 이미지 전체를 요약하는 **전역 token**. 분류는 기본적으로 이 CLS-only 임베딩을 쓴다(`cls_weight=1.0, patch_mean_weight=0.0`).
- **layer 깊이의 의미**: 얕은 층일수록 표면/질감, 깊은 층일수록 카테고리 의미로 수렴. 이게 핵심 직관이다.

### 3.3 두 모듈의 layer 소유권 분리

| | 어느 layer | 무엇을 보나 | 표현 |
|---|---|---|---|
| **분류기** | 최종(`last_hidden_state`, base=L12) | semantic 카테고리 | CLS 전역 임베딩 → cosine KNN |
| **결함** | 중간(`hidden_states[L+1]`, base L5~8) | 국소 표면 패턴 | mask 내 patch token L2 거리 |

같은 crop·같은 backbone을 공유하므로 객체당 **forward 1회**면 충분하다(feature 캐시). layer 컨벤션은 PatchCore식으로 **L번째 블록 통과 후 출력 = `hidden_states[L+1]`**이다.

### 3.4 왜 ablation에서 최종 layer(L12)를 일부러 제외하나

layer ablation은 각 클래스에서 어느 중간 layer가 결함을 가장 잘 살리는지 AUROC로 비교하는 실험이다. 여기서 **L0(블록 통과 전)과 L12(분류용 semantic)는 후보에서 뺀다.** L12 제외 이유:

1. **분류가 이미 L12를 쓴다** — 굳이 결함이 또 쓸 필요가 없고,
2. **L12는 semantic이라 anomaly 거리가 죽는다** — 정상/긁힘을 같은 카테고리로 수렴시키니 L2 거리를 재도 결함이 정상 분포 밖으로 안 튄다.

실측 패턴: 얕은 L1~3은 낮고 → **중간 L5~8이 sweet spot** → L10에서 dip(semantic transition) → L11 살짝 회복.

### 3.5 클래스마다 best layer가 왜 다른가

base 기준 ablation 결과:

| class | best layer | best AUROC | 비고 |
|---|---|---|---|
| metal_case | **L7** | 0.999 (SEPARATED) | rigid 금속 표면 |
| pencil_case | **L5** | 0.996 | |
| haribo | **L5** | 0.942 | deformable |
| 젤리껌(mango) | **L8** | 0.870 | 별도 tear 벤치(`MANGO_QUANT_EVAL`) 출처 |

결함 유형과 표면 물성이 다르기 때문이다. 긁힘 같은 **미세 질감**은 더 얕은 층(pencil/haribo L5)에서, 금속의 좀 더 **구조적인 표면 이상**은 약간 깊은 층(metal L7)에서 잘 튄다. "어느 칸에서 그 결함이 가장 도드라지나"는 클래스마다 실험으로 정한 값이지, 한 값을 모두에 강요하지 않는다.

> **출처 분리(정확성)**: metal/pencil/haribo의 best layer는 **3클래스 ablation** 결과(`LAYER_ABLATION_REPORT`)다. mango의 L8 근거는 같은 실험의 4번째 행이 아니라 **별도 tear 벤치마크** 산출물이다. "한 실험에서 4클래스를 다 뽑았다"고 말하면 틀린다.

> **정직성 — staged 상태**: config에는 클래스별 best layer(metal L7, pencil/haribo L5)를 반영했지만 **운영 memory bank는 아직 L8**이다. 해당 layer로 **재빌드 + threshold 재튜닝** 전까지 PatchCoreLite의 layer 가드가 로드 시 ValueError로 멈춘다. layer 값은 확정했으나 bank 반영은 후속 작업이다.

### 3.6 이렇게 답하세요

> **Q. DINOv2를 새로 학습시켰나요?**
> "아니요. 라벨 없이 사전학습된 ViT 백본을 가져와 freeze한 채 feature만 추출합니다. 학습 비용이 없고, 분류와 결함이 같은 backbone을 공유합니다."

> **Q. 분류와 결함이 신호가 안 겹치는 이유는?**
> "다른 깊이를 읽으니까요. 분류는 카테고리로 수렴한 최종 층, 결함은 표면이 살아있는 중간 층. 최종 층은 정상/긁힘을 한 단어로 부르지만 중간 층은 긁힘을 튀게 합니다. 그래서 상보적입니다."

> **Q. large 모델(24블록)로 바꾸면 layer는?**
> "최적 layer는 절대 위치가 아니라 **상대 깊이**로 옮겨진다는 게 prior입니다(×2 어림: haribo/pencil ~L10, metal ~L14, sweet spot 대략 L10~16). 단 base는 large에서 distill된 모델이라 1:1 대응 보장이 없어, **데이터로 재-ablation해서 확정**해야 합니다."

### 3.7 발표자가 외워야 할 숫자 (왜곡 금지)

- patch 분해: **224 입력 → patch_size 14 → 16×16 = 256 token**, base 768 / large 1024.
- 분류 임베딩 기본 = **CLS-only**(`cls_weight=1.0, patch_mean_weight=0.0`).
- best layer: **metal L7 / pencil·haribo L5 / mango L8** (base 기준). 운영 bank는 **현재 L8**(staged).
- ablation 제외: **L0와 L12**. mid **L5~8 sweet spot**, L10 dip, L11 회복.
- layer 컨벤션: **`hidden_states[L+1]`** (= L번째 블록 통과 후).

## 4. 분류 로직 — DINOv2 KNN과 unknown 게이팅

### 4.1 한 문장 직관

분류기는 학습된 신경망 헤드가 아니라, **도감(reference bank)에 붙여 보고 제일 닮은 무리를 고르는 닮은꼴 찾기**다. 그리고 닮은꼴이 영 미덥지 않으면 4명의 깐깐한 심사위원 중 한 명만 거부해도 **"모름(unknown)"으로 빼버린다.**

### 4.2 왜 이렇게 설계했나

**왜 학습 헤드가 아니라 KNN인가.** 새 클래스를 추가할 때 분류 헤드를 다시 학습시키고 싶지 않기 때문이다. DINOv2 backbone은 그대로 두고, 각 클래스의 **정상 객체 임베딩만 도감에 모아두면** 분류기가 완성된다. 결함 탐지가 "정상 patch만 모아 memory bank를 만든다"는 normal-only 철학과 같은 맥락이다.

> ⚠️ **두 bank를 혼동 금지**: 분류용 **reference bank**(클래스 카테고리를 가르는 도감)와 결함용 **memory bank**(표면 이상을 보는 정상 patch 모음)는 별개다.

**왜 unknown 게이트가 필요한가.** 도감에 없는 처음 보는 물체가 들어와도 KNN은 무조건 "가장 가까운 무리"를 답으로 내놓는다. 그래서 **"고르긴 골랐는데 영 안 닮았다"를 걸러낼 문지기**가 필요하다. 이 문지기가 unknown gating이고 보수적으로 설계됐다 — 의심스러우면 결함 탐지로 넘기지 않고 unknown으로 우회시킨다.

### 4.3 메커니즘 1 — KNN 분류로 class_index 뽑기

1. crop을 DINOv2에 통과시켜 **최종 layer** 전역 임베딩을 얻는다(기본 CLS-only).
2. 이 임베딩을 reference bank 표본들과 **cosine 유사도**로 비교한다.
3. 최근접 top-k를 뽑아 **클래스별로 투표**시킨다. 가장 표를 많이/세게 받은 클래스가 `class_index`.

### 4.4 메커니즘 2 — unknown gating(4개 조건의 OR-트립)

승자 클래스가 정해진 뒤 네 게이트를 **모두** 통과해야 살아남는다. **하나라도 미달이면(트립하면) unknown(5)으로 우회** — AND가 아니라 OR-트립이다.

| 게이트 | 본다는 것 | 직관 |
|---|---|---|
| `min_class_score` | 승자 클래스 점수가 충분한가 | "점수 심사위원" |
| `min_similarity` | 최근접 이웃 cosine 유사도가 충분한가 | "유사도 심사위원" |
| `min_vote_ratio` | 승자 득표 비율이 충분한가 | "득표 심사위원" |
| `min_margin` | 승자와 차순위 격차가 충분한가 | "격차 심사위원" |

```
is_unknown = (class_score < min_class_score)
          OR (similarity   < min_similarity)
          OR (vote_ratio   < min_vote_ratio)
          OR (margin        < min_margin)
```

**margin이란.** 승자 클래스 평균 cosine과 차순위 클래스 평균 cosine의 차이다. top-k에 **단일 클래스만 있으면 비교 대상이 없어 `+inf`** — 이 경우 margin 게이트는 자동 통과한다.

> **라벨 shift 주의.** bank 라벨은 `{1..5}`로 저장돼 있다. 이를 **0-based로 한 칸 내린(`labels − 1`)** 뒤에야 `UNKNOWN_CLASS_ID=5` 매핑이 성립한다. 순서를 빠뜨리면 클래스 인덱스가 전부 어긋난다.

### 4.5 메커니즘 3 — confidence는 확률이 아니다 (가장 자주 오해받는 지점)

출력 필드 `confidence`(=`class_score`)는 **승자 클래스 이웃들의 softmax 가중합**이다. "이웃이 얼마나 손을 들어줬나"의 가중 합산이지, 정규화된 확률이 아니다.

- 모든 클래스 점수를 더해도 **1(100%)이 안 될 수 있다.**
- 따라서 `confidence=0.9`를 "90% 확실"이라 부르면 **틀린 해석**이다.
- 직관: 확률 분포가 아니라 **득표 점수판**이라고 생각하라.

### 4.6 이렇게 답하세요

> **Q. 분류기가 학습된 모델인가요, KNN인가요?**
> "KNN입니다. DINOv2 최종 layer 임베딩을 reference bank와 cosine 비교해 가장 닮은 무리로 투표 분류합니다. 분류 전용으로 학습시킨 헤드가 아닙니다."

> **Q. 처음 보는 물체가 들어오면요?**
> "4개 게이트(점수·유사도·득표·격차) 중 하나라도 미달이면 unknown(5)으로 빠지고 결함 탐지를 우회합니다. 억지로 한 클래스로 우기지 않습니다."

> **Q. confidence 90%면 90% 확실한 거 아닌가요?**
> "아닙니다. 이웃 softmax 가중합이라 정규화된 확률이 아니에요. 클래스 점수 합이 1이 안 될 수도 있어서 '확률'로 읽으면 안 됩니다."

> **Q. 분류기는 기본으로 켜져 있나요?**
> "아니요, `classifier.enabled`가 **기본 False**입니다. 로드되지 않으면 인스턴스에 `class_index`가 부착되지 않고, 그러면 결함 라우팅 입력 자체가 비게 됩니다."

### 4.7 정직성 노트

이 분류 결과(`class_index`)가 결함 탐지로 라우팅되는 지점은 **설계됐으나 `pick_n_place.py`에는 아직 미배선**이다. 게이팅 임계값과 운영 수치는 합성 결함·LOO·단일 seed 기반이라 실물 재검증 대상이다.

## 5. 왜 클래스마다 다른 전략을 쓰나 — 물성이 전략을 정한다

### 5.1 한 줄 직관

> **검사 도구는 물건에 맞춘다.** 쇠판처럼 안 흔들리는 표면은 자(단일 측정) 하나로 충분하고, 구겨지는 봉지는 여러 증거를 모아 다수결로 판정한다. 같은 "결함탐지"라도 객체의 **물성**과 **정상이 얼마나 들쭉날쭉한가**가 전략을 결정한다.

핵심 질문은 "왜 한 방법으로 통일하지 않았나"다. 답: **정상의 모양이 클래스마다 다르기 때문**이다. 결함은 "정상에서 벗어난 것"으로 정의되는데, 정상 자체가 흔들리면(deformable) 단일 신호가 정상 변형까지 결함으로 오인한다.

### 5.2 두 개의 축

**축 1 — rigid vs deformable.**
- **rigid(필통·메탈케이스)**: 단단한 표면 → 정상이 항상 거의 같은 모양 → 결함만 도드라짐 → **단일 신호(PatchCore L2)로 충분**.
- **deformable(하리보)**: 무른 표면 → **정상도 구겨진다** → 단일 신호는 정상 구겨짐을 결함으로 오인(false reject) → **다수결**해야 안전.

**축 2 — 정상 변동성 CV(변동계수 = 표준편차/평균).**
- CV가 **낮으면** 정상 분포가 좁은 '띠' → 결함이 띠 밖으로 잘 튄다 → PatchCore가 잘 먹힌다.
- CV가 **높으면** 정상 띠가 넓다 → 결함이 정상 띠 안에 묻힌다 → 단일 신호로 못 가른다.

> **직관 훅**: CV 0.126 = "정상끼리 거의 안 흔들린다". 정상 띠가 좁으니 결함이 띠 밖으로 잘 튀어 단일 신호만으로도 잘 잡힌다. 이게 mango가 'rigid급으로 타이트하다'는 말의 뜻이다.

### 5.3 라우팅 표 (class_index → DefectRegistry → 전용 detector)

| id | class(코드명) | detector | 이유(한 줄) |
|---|---|---|---|
| 0 | 하리보 (haribo) | **Cascade** (≥2/4 voting) | deformable — 정상 구겨짐을 결함과 구분하려면 다수결 |
| 1 | 젤리껌 (mango) | **Fusion** (w=0.25) · `enabled:false` | 캔디류지만 정상이 rigid급 타이트(CV 0.126) → 단일신호+기하보조 |
| 2 | 필통 (pencil_case) | **PatchCore** (max) | rigid — 단일 신호로 충분 |
| 3 | 메탈케이스 (metal_case) | **PatchCore** (max) | rigid — 단일 신호로 충분 |
| 4 | 물병 (bottle) | **제외** | 투명 plastic → 빛 투과로 mask에 타 객체 patch 혼입 |
| 5 | 언노운 (unknown) | **우회** | classifier가 거름 |

### 5.4 세 전략을 한 문장씩

- **PatchCore-lite (rigid)**: 정상 patch만 모은 memory bank에서 테스트 patch의 최근접 L2 거리를 재고, 점수가 임계를 넘으면 결함. 자 하나로 재는 단일 측정. (필통 τ=9.2 / 메탈 τ=6.0)
- **Cascade (하리보)**: 4신호(PatchCore L2 / color Mahalanobis / normal Laplacian / mask topology)가 각자 임계를 넘으면 1표씩, **≥2표면 결함**. 정상 구겨짐은 PatchCore 1표에 그치지만, 찢김은 색·기하·형상 신호가 동시에 떠 2표 이상. **AND-gate가 아니라 "임계 충족 신호 ≥2개"의 다수결.**
- **Fusion (mango)**: `fused = (1−w)·z_pc + w·z_lap`, **w=0.25**. PatchCore가 주신호(0.75), normal Laplacian이 기하 보조(0.25). 가벼운 2신호 융합.

### 5.5 mango의 역설 — 가장 자주 받을 질문

> **청중 질문: "하리보랑 젤리껌, 둘 다 사탕봉지 아닌가? 왜 전략이 다른가?"**

둘 다 캔디류지만 **정상 분포가 다르다.** mango는 bulk 정상 CV가 **0.126**으로 rigid급으로 타이트하다. '겉보기엔 봉지인데 속은 빳빳한' 예외 케이스라, 하리보처럼 봉지용 4신호 다수결을 쓸 필요가 없다.

cascade를 안 쓴 두 가지 실무 이유:
1. **임계 튜닝 부담**: cascade는 4개 신호 임계를 다 맞춰야 한다. 정상이 이미 타이트하면 과하다.
2. **color 기여가 낮다**: mango는 다색 인쇄라 color outlier 신호가 잘 안 먹힌다.

그래서 결함 모드가 찢김(tear)인 점을 살려 **단일신호(PatchCore) + 기하 보조(Laplacian)의 가벼운 융합**으로 갔다.

> **이렇게 답하세요**: "물성이 아니라 **정상 분포**로 갈렸습니다. mango는 정상 CV가 0.126으로 rigid급이라 봉지용 4신호 다수결이 과하고, 다색 인쇄라 color 신호도 약해서, 단일신호+기하보조의 가벼운 fusion으로 갔습니다."

### 5.6 bottle은 왜 아예 뺐나

bottle은 투명 plastic이라 빛이 투과한다. 그러면 mask 안으로 **뒤에 있는 다른 객체의 patch가 섞여 들어온다**. 정상 patch bank 자체가 오염되니 "정상에서 벗어났는지"를 잴 기준이 무너진다. 알고리즘 문제가 아니라 입력(mask)이 깨지는 문제라 제외했다.

> **이렇게 답하세요**: "투명해서 빛이 투과하면 mask 안에 뒤 객체 patch가 섞입니다. 비교 기준인 정상 분포가 오염되므로 뺐습니다."

### 5.7 정직성 노트 / 최종 답

- **mango는 운영 비활성(`enabled:false`)**. Fusion의 Laplacian 채널 TPR은 합성결함이 RGB만 바꿔(normal map 미변경) 검증 불가 → 실물 찢김 테스트 전까지 막아뒀다. w=0.25도 "실제 찢김은 기하 신호를 남긴다"는 미최적화 prior이며 `lap_mu/sigma`가 placeholder(0/1)라 현재 실효 lap 기여는 매우 작다.
- mango AUROC **0.704→0.880**은 **fusion이 아니라 PatchCore(max) 단독값**이다. 개선은 라벨 오염 제거 + bank v2 + 비율 tear 덕분이지 "fusion이 0.88을 만들었다"가 아니다.
- detector는 아직 `pick_n_place.py`에 **미배선**(action 피드백도 미연결), layer는 staged(운영 bank L8), 모든 수치는 base·합성결함·LOO·단일 seed라 **실물 재검증 대상**.

> **"왜 통일 안 하나"에 대한 최종 답**: 결함의 정의가 "정상에서의 이탈"인데, **정상의 모양(물성·CV)이 클래스마다 다르기 때문**입니다. rigid·타이트한 정상은 자 하나(PatchCore), 흔들리는 정상은 다수결(Cascade), 타이트하지만 찢김이 관심사인 mango는 단일신호+기하보조(Fusion) — 도구를 물건에 맞춘 겁니다.

## 6. 세 detector 상세

### 6.1 PatchCore-lite — 정상 patch 도감과의 최근접 거리

**직관**: 정상 객체들을 잘게 조각(patch)내어 도감(memory bank)을 만든다. 테스트 객체도 조각으로 쪼개 **각 조각을 도감에서 가장 닮은 정상 조각과 비교**한다. 아무리 뒤져도 닮은 게 없는 조각이 하나라도 있으면 — 거기가 결함이다. "닮은 정도"를 재는 자가 **L2 거리**(유클리드 거리)다. 거리가 멀수록 "안 닮았다 = 정상에서 멀다".

> **왜 L2(거리)이고 cosine(방향)이 아닌가**: 결함은 "국소 표면이 정상에서 얼마나 떨어졌나"라는 **거리 척도**라 절대적 변화량을 보는 L2가 자연스럽다. 카테고리 판정은 cosine을 쓰는 분류기가 따로 맡는다.

**메커니즘:**

1. **오프라인 bank 빌드.** 정상 객체 crop(224×224) → DINOv2 중간 layer → 16×16 grid patch token 중 mask 안쪽 것만 누적해 `.npz` 저장. PatchCore[Roth 2022]의 경량판인 이유는 여기 있다 — 원본의 coreset subsampling(대표 조각만 추리는 압축)을 생략하고 **전 patch를 그대로 bank에 담는다.**
2. **온라인 조각별 최근접 거리.** 각 patch q에 대해 `nn_dist(q) = min_m ‖q − m‖₂`. 실제 계산은 `(a−b)² = a²+b²−2ab` 전개로 행렬곱 1회에 끝낸다(속도 트릭, 결과 동일).
3. **aggregate(조각 점수 → 이미지 1점).** `max`(가장 튄 조각 하나) / `top_k_mean(k=4)` / `top_p_mean(p=0.01)`. (코드 분기가 `else=top_p_mean`이라 `"max"`/`"top_k_mean"` 외 오타는 조용히 top_p_mean으로 떨어진다.)
4. **판정.** `score > τ`면 결함. τ는 코드 하드코딩이 아니라 **yaml 주입값**(오프라인 ROC 튜닝 산출, §7).
5. **heatmap.** 조각별 nn_dist를 16×16 grid에 도로 흩뿌린 뒤 bilinear 확대. **빨갈수록 정상에서 먼 조각** = 의심 자리.

**왜 현행 config는 전부 aggregate=max 인가.** `max` = "**한 군데라도 크게 어긋나면 불량**". 작은 결함은 본질적으로 **소수의 조각만** 건드리므로, 평균 계열(top_k_mean, top_p_mean)은 멀쩡한 조각에 희석되어 작은 결함 신호가 묻힌다. 그래서 현행 배포 config는 pencil/metal/mango 전부 `patch_aggregate: max`다. 실측 근거: mango에서 top_k로 바꾸면 AUROC가 0.880→0.816으로 떨어진다(소형 tear 희석).

> 한 가지 구분: top_k_mean이 글레어(반사) 같은 단일 outlier를 완화하는 효용은 있다. 하지만 **현행은 max를 채택했고**, 반사 오탐을 줄이는 책임은 주로 **layer 선택**이 진다. metal_case가 SEPARATED(FPR 4%→1%)에 도달한 것은 aggregate가 아니라 **L7 layer 효과**다.

**이렇게 답하세요:**

> **Q. 객체 patch가 없거나 crop이 실패하면?**
> "`score=0.0, is_defect=False`로 **silent 반환**됩니다. 추출 실패가 '결함 아님'으로 처리되므로 **false-negative 위험**이 있습니다 — 통합 시 주의할 지점입니다."

> **Q. threshold는 어떻게 정했나?**
> "코드 상수가 아니라 yaml 주입값입니다. 정상 LOO 분포와 합성 결함 분포로 오프라인 ROC를 그려 balanced TPR/specificity 기준으로 튜닝합니다(§7)."

### 6.2 Cascade(하리보) — 4신호 다수결(AND 아님)

**왜 이렇게 했나.** 하리보는 물렁한(deformable) 객체다. 손으로 집으면 **구겨진다**. 그런데 구겨짐도 표면이 변형되고, **찢김(결함)**도 표면이 변형된다 — 둘 다 "표면이 평소와 다르다"는 신호를 똑같이 만든다. PatchCore **하나만** 쓰면 구겨진 정상 하리보를 "뱅크에 없는 모양 → 결함!"이라고 **오인(false reject)**하기 쉽다.

설계 결론: **신호 하나의 말만 믿지 말고, 서로 독립인 증인 4명을 세운 뒤 과반(2명 이상)이 동의할 때만 결함이라고 판정하자.**

> **직관 훅 — 배심원 4명**: 4명 중 **2명 이상**이 유죄여야 결함. 한 명이 잘못 흔들려도 평결은 안 뒤집힌다. 정상 구겨짐은 PatchCore 한 명만 의심 → 1표 → 무죄. 진짜 찢김은 색·모양·기하 증인이 함께 나와 2표+ → 유죄. **단, '과반'이지 '전원 만장일치(AND)'가 아니다.**

**4개의 독립 신호** (임계 전부 `configs/defect_detection.yaml`의 haribo 블록에서 런타임 주입, 코드 상수 아님; 각 신호는 픽셀 단계 + vote 단계의 **2단 임계**):

| # | 신호 | 무엇을 보나 | 픽셀 단계 임계 | vote 임계 |
|---|---|---|---|---|
| s1 | **PatchCore L2** | 표면 patch가 정상 뱅크에서 얼마나 먼가 | — | `8.6` |
| s2 | **Color outlier ratio** (LAB GMM Mahalanobis) | 정상 색 분포에서 벗어난 픽셀 비율 | Mahalanobis > z=3.0 | `0.10` |
| s3 | **Normal Laplacian peak** | 표면 법선의 기하적 불연속 픽셀 비율 | \|∇²n_z\| > 0.30 | `0.05` |
| s4 | **Mask topology raggedness** | 윤곽 너덜거림, `P²/(4π·A)`(원이면 1) | — | `1.8` |

직관: s1="무늬가 낯설다", s2="색이 이상하다", s3="기하가 꺾였다", s4="외곽선이 너덜거린다". **정상 구겨짐은 보통 s1만 자극** → 1표. **찢김은 s2·s3·s4를 동시에** 건드린다(속살 색 노출 + 찢긴 단면 기하 불연속 + 너덜한 윤곽).

**판정은 votes로, score는 로깅용:**

```
votes = 𝟙[s1>8.6] + 𝟙[s2>0.10] + 𝟙[s3>0.05] + 𝟙[s4>1.8]
is_defect = (votes ≥ voting_min)     # voting_min = 2
score = max(s1, s2, s3, s4)          # 보고/로깅용 스칼라 — 판정엔 미사용
```

세 가지를 정확히:
1. **판정은 전적으로 `votes`다.** 임계를 넘은 신호 **개수**가 2 이상이면 결함.
2. **`score = max(s1..s4)`는 판정에 안 쓴다.** 단위가 전부 다른 4값(거리 8.6 / 비율 0.10 / 비율 0.05 / 무차원 1.8)의 max라 **결함 강도 척도가 아니다.** 로깅·디버그용.
3. **AND-gate가 아니다.** 코드 주석에 "AND gate"라 적혀 있으나 이는 **오기**다. 실제 의미는 **임계 충족 신호 ≥2의 다수결**이다.

**강건성**: 단일 신호 임계라면 그 신호가 한 번 오작동할 때 바로 오판. 다수결은 **개별 신호의 false 한 건이 최종 판정을 못 뒤집는다.**

**Fallback**: normal map이 안 들어오면 **s3=0** 처리 → 사실상 3신호(s1·s2·s4) 다수결(임계 2 유지라 더 보수적). contour 추출 실패 시 **s4=정상값**으로 둬 함부로 1표를 주지 않는다(raggedness 임계를 1.0 미만으로 설정하면 빈 contour가 항상 1표가 되는 함정 — 현재 1.8이라 안전).

**이렇게 답하세요:**

> **Q. 이거 AND 조건인가요? (4개 다 떠야 결함?)**
> "아닙니다. 임계 넘은 신호가 **2개 이상**이면 결함인 다수결(≥2 of 4)입니다. 코드 주석의 'AND gate'는 오기이고, 실제는 과반 voting입니다."

> **Q. score랑 votes 중 뭐로 판정하나요?**
> "votes입니다. score=max(s1..s4)는 단위가 다른 값들의 max라 강도 척도가 아니고 로깅 전용입니다."

> **운영점**: TPR 81% / FPR 5%, AUROC 0.929(best L5 기준 0.942). 합성 결함 + LOO + 단일 seed 기반이라 실물 재검증 대상. layer(haribo L5)는 staged(운영 뱅크 L8).

### 6.3 Fusion(젤리껌/mango) — 단일신호 + 기하 보조의 z-가중 융합

**한 줄 직관: 주심(PatchCore)이 판정하고, 부심(기하)이 0.25만큼 거든다 — 단 부심은 아직 자격검증 중이라 경기 투입 보류.**

젤리껌은 정상 분포가 **rigid급으로 타이트**(CV 0.126)해서 정상 manifold 이탈을 재는 **PatchCore 단일 신호만으로도 주신호로 충분**하다. 그런데 대표 결함 모드가 **찢김(tear)**이라 표면 기하가 튄다(찢긴 경계에서 법선이 불연속으로 꺾인다). 이 "기하 흔적"을 PatchCore 주신호에 **보조로 살짝 얹은 것**이 fusion이다. (cascade를 안 쓴 이유는 §5.5 참조.)

**메커니즘 — z-정규화로 단위가 다른 두 점수를 더할 수 있게 만든다.** PatchCore는 **L2 거리**(수 단위), Laplacian은 찢김 경계 픽셀의 **비율**(0~1)이다. z-정규화는 둘을 "각자의 평균에서 표준편차 몇 칸 벗어났나"로 환산하는 환율 변환이다.

```
z_pc  = (pc_score − pc_mu) / pc_sigma      (pc_mu=7.95, pc_sigma=1.18, max aggregate 기준 정상 LOO 통계)
z_lap = (lap_ratio − lap_mu) / lap_sigma   (lap_mu=0, lap_sigma=1 — 미실측 placeholder)
fused = (1 − w)·z_pc + w·z_lap             (w = 0.25 → PatchCore 0.75, Laplacian 0.25)
is_defect = fused > threshold(1.8)
```

- **Laplacian 채널이란**: normal map의 z성분에 2차 미분(Laplacian)을 걸어 절댓값이 peak를 넘는 픽셀 비율이다. 평평한 표면에선 ~0, 찢긴 경계에선 기하가 급격히 꺾여 peak가 뜬다 = **찢김 경계의 흔적**. (구현상 mask를 7px erosion으로 침식해 윤곽의 정상적 불연속은 배제하고 내부만 본다.)

**w=0.25는 측정값이 아니라 prior다.** 데이터로 최적화한 값이 아니라 "실제로 찢기면 표면 기하가 튄다"는 상식에 근거해 **잠정 부여한 가중치**다.

> **이렇게 답하세요 (w는 어떻게 정했나?)**: "최적화 값이 아니라 prior입니다. '찢기면 기하가 튄다'는 사전지식으로 0.25를 잠정 부여했고, 실물 찢김 데이터로 검증·조정할 예정입니다."

**왜 검증 못 하고 `enabled:false`인가.** 임계를 튜닝하려면 결함 분포가 필요한데 합성 결함 생성기로 만든다. 그런데 **합성 결함은 RGB(색)만 바꾸고 normal map은 건드리지 않는다**(normal을 바꾸려면 Zivid PLY 자체 조작 필요). 결과적으로 합성 데이터에는 진짜 찢김의 기하 흔적이 없어 **Laplacian 채널의 TPR 기여를 오프라인에서 검증할 길이 없다.** FPR 쪽은 정상 데이터로 캘리브 가능하나 현재 `lap_mu=0, lap_sigma=1` placeholder만 박혀 있다. 검증 안 된 신호를 켜는 건 위험하므로 per-class `enabled:false`로 막아 둔다(실물 찢김 테스트 후 전환 예정).

**결정적 함정: 0.880은 fusion 성능이 아니다.** 운영점 표의 mango `0.704→0.880`은 **PatchCore(max aggregate) 단독값**이다. 개선 출처는 (1) 라벨 오염 1건 제거, (2) memory bank v2(309 obj), (3) 비율 기반 tear 합성(객체 크기 달라도 tear 점유율 일정 → mango 스케일 희석 해결) 세 가지다. **Laplacian 융합 기여는 합성으로 검증 불가라 이 수치에 들어 있지 않다.**

> **이렇게 답하세요 (0.880은 fusion 성능 아닌가?)**: "아닙니다. PatchCore 단독값입니다. 라벨오염 제거 + bank v2 + 비율 tear 합성 덕분이고, Laplacian 융합 기여는 합성으로 검증 못 해 이 숫자에 포함돼 있지 않습니다."

> **운영점**: TPR 70% / FPR 5%, layer L8, aggregate max(top_k_mean이면 0.880→0.816). `enabled:false`.

## 7. 오프라인 캘리브 — bank 빌드 · 임계 튜닝 · layer 선택

### 7.1 왜 오프라인 캘리브가 필요한가

결함 탐지기는 "결함이 뭔지" 배운 적이 없다. 정상만 모아 놓고 거기서 벗어나면 결함이라 판정하므로, 운영 전에 세 가지를 깔아 둬야 한다(순서 있음).

1. **무엇이 정상인가** → memory bank 빌드
2. **얼마나 벗어나야 결함인가** → 임계(threshold) 튜닝
3. **어느 배율로 봐야 결함이 가장 잘 보이는가** → layer ablation

bank를 만들어야 거리를 잴 수 있고, 거리를 재야 임계를 그을 수 있고, 어느 layer가 좋은지 알아야 그 layer로 bank를 다시 만든다. **이 세 단계는 아직 "한 바퀴 더" 돌아야 하는 staged 상태**다(§7.5).

### 7.2 A. Memory bank 빌드 — 정상이 뭔지 기억시키기

모범 답안만 잔뜩 모아 둔 노트. 채점할 때(운영) 학생 답안을 이 노트와 대조해 "노트에 없는 패턴"이 나오면 의심한다.

메커니즘(`scripts/build_patchcore_refs.py`): 라벨 polygon에서 **정상 객체만** crop(224×224, 패딩 0.03, 배경 gray 127) → DINOv2 중간 layer → patch token(16×16=256, base D=768) 중 **mask 안쪽만** 누적 → `.npz` 저장. 메타에 `dinov2_layer`/`input_size`/`class_id`/`patches_per_object`를 박는다.

**메타가 왜 중요한가**: bank가 "나는 L8에서 만들어졌다"를 기록하므로, 나중에 L5 config로 이 bank를 쓰려 하면 가드가 즉시 `ValueError`로 멈춘다. layer가 다른 patch끼리 거리를 재면 숫자가 무의미한데, 이를 **조용히 통과시키지 않고 시끄럽게 차단**한다.

> ⚠️ **재빌드 시 사고 1순위**: 빌드 스크립트의 `--class_id`는 **classifier 출력 인덱스가 아니라 polygon class_id**(라벨링 raw label, 예: haribo=1, metal_case=4)다. classifier index(haribo=0, metal=3)와 혼동하면 엉뚱한 클래스 bank가 만들어진다.

### 7.3 B. 임계 튜닝 — 정상 산과 결함 산 사이에 경계선 긋기

정상 점수들로 산 하나, (합성)결함 점수들로 산 하나를 그려 놓고 **두 산을 가장 잘 가르는 위치**를 자동으로 찾는다(`scripts/synth_roc_tune_loo.py`).

**B-1. LOO가 왜 반드시 필요한가 (self-match 함정).** 시험 문제를 출제자가 직접 풀면 100점이다 — 실력 측정이 아니다. 정상 객체 i의 patch가 bank에 그대로 있으면 i의 patch는 bank에서 **자기 자신과 매칭**되어 최근접 거리가 0이 된다(self-match). 그래서 **LOO(Leave-One-Out)**: 객체 i를 채점할 땐 i의 patch를 bank에서 빼고 나머지로만 거리를 잰다.

**B-2. 결함 데이터가 없는데 결함 산은 어떻게.** **합성 결함**을 만든다(`synthesize.py`). 정상 crop 위에 인공으로 scratch(어두운 선 3~7개)나 tear(경계 밴드에 속살색 blob)를 덮어 결함 분포를 만든다. 객체당 **5개 변형**을 합성하므로 정상:결함 ≈ **1:5 불균형**이다.

**B-3. 'F1-best'는 오해 표기다 — 정확히는 balanced TPR/specificity.** 코드/문서에 "F1-best"라고 적혀 있지만 **표준 F1이 아니다.** 실제 최적화 식:

```
τ* = argmax  2·TPR·(1−FPR) / ( TPR + (1−FPR) )
```

이건 precision 기반 표준 F1이 아니라 **TPR(민감도)과 (1−FPR)=specificity의 조화평균**이다. **ROC 곡선만으로는 precision을 구할 수 없기** 때문에(precision은 정상:결함 비율에 의존하는데 여기선 1:5 합성 비율이라 의미가 흔들린다) 비율에 덜 휘둘리는 TPR/specificity 균형점을 택했다.

**B-4. layer-aware 튜닝.** 튜너는 각 bank의 `dinov2_layer` 메타를 읽어 **테스트 patch도 같은 layer에서** 뽑는다(예전엔 L8 하드코딩 버그가 있었고 수정됨).

### 7.4 C. Layer ablation — 클래스마다 다른 현미경 배율 찾기

현미경 배율을 바꿔 가며 결함이 가장 선명한 배율을 찾는다. **얕은 layer는 흐릿**(L1~3, 저수준 텍스처뿐), **너무 깊은 layer는 결함을 카테고리로 뭉갠다**(L12는 "metal 정상"과 "metal 스크래치"를 같은 'metal'로 수렴). **중간 L5~8이 sweet spot.**

메커니즘(`scripts/layer_ablation_*.py`): `output_hidden_states=True`로 forward 1회에 L1~L11을 동시 추출 → **layer × class AUROC 표** → 클래스별 best layer 선택. L12는 classifier가 이미 쓰고 semantic이라 **명시 제외**.

base(dinov2-base) 결과는 §3.5 표 참조(metal L7 / pencil·haribo L5 / mango L8). 전체 패턴: 얕은 L1~3 낮음 → mid L5~8 sweet spot → L10 dip → L11 회복.

### 7.5 D. 정직한 현재 상태 — layer는 staged, 가드가 막고 있다

**config에는 클래스별 best layer가 이미 반영됐지만(haribo/pencil L5, metal L7), 운영 memory bank는 아직 L8이다.** config(L5/L7)와 bank(L8)가 어긋나 있고, 이 상태로 로드하면 §7.2 layer 가드가 `ValueError`로 막는다. **버그가 아니라 의도된 안전장치**다 — layer 어긋난 채로 의미 없는 거리를 재느니 시끄럽게 멈추는 게 낫다.

best layer를 실제로 쓰려면 **그 layer로 bank 재빌드 → 그 분포로 τ 재튜닝**을 한 바퀴 더 돌아야 한다. 현재 threshold들(예: metal 6.0은 L7 참고 τ=5.76을 보수적으로 절상)도 재튜닝 대기 placeholder다.

> ⚠️ **운영점 수치 주의**: §6 표의 metal "TPR 100% / FPR 4%"는 **L8@τ=8.93 측정값**이다. config가 채택한 L7은 FPR≈1%(별도 측정, SEPARATED)이라 운영점 수치와 채택 layer가 아직 어긋나 있다. 재빌드 후 L7 기준으로 다시 측정해야 한다.

### 7.6 이렇게 답하세요

> **Q. self-match가 뭐고 왜 LOO를 하나요?**
> "정상 patch를 bank에 넣어 두고 그 객체를 채점하면 자기 자신과 거리 0으로 매칭돼 무조건 정상으로 나옵니다. 그래서 채점할 객체는 bank에서 빼고(Leave-One-Out) 나머지로만 점수를 냅니다."

> **Q. 결함 데이터가 없다면서 임계는 무슨 결함으로 맞췄나요?**
> "정상 위에 합성 scratch/tear를 입혀 결함 분포를 만들었습니다. 객체당 5변형이라 정상:결함이 1:5입니다. 다만 합성은 RGB만 바꾸고 normal/depth는 못 바꿔서 도메인 갭이 있고, 최종 수치는 실물 재검증 대상입니다."

> **Q. 'F1-best'라던데 진짜 F1인가요? 임계는 사람이 손으로 정했나요?**
> "사람이 손으로 정한 게 아니라 ROC에서 자동 산출해 yaml에 주입한 값입니다. 다만 'F1-best'는 오해 표기고, 정확히는 TPR과 specificity의 조화평균을 최대화하는 점입니다. ROC만으론 precision을 못 구해서 표준 F1을 쓸 수 없었습니다."

> **Q. layer를 config에 넣었다면서 왜 아직 L8 bank인가요?**
> "ablation으로 best layer는 정했지만, 그 layer로 bank를 재빌드하고 임계를 재튜닝하는 작업이 남아 있습니다. config(L5/L7)와 bank(L8)가 어긋난 동안은 가드가 일부러 로드를 막습니다. staged 상태고, 한 바퀴 더 돌면 활성화됩니다."

### 7.7 한눈 요약 (암기용)

- **3단계**: ① 정상 patch로 bank 빌드 → ② LOO ROC로 임계 산출 → ③ layer ablation으로 best layer 선택
- **LOO** = 채점할 객체는 bank에서 빼기(self-match=거리 0 함정 회피)
- **임계 지표** = balanced TPR/specificity(`argmax 2·TPR·(1−FPR)/(TPR+(1−FPR))`), 표준 F1 아님. ROC 산출 → yaml 주입
- **결함 분포** = 합성 scratch/tear, 객체당 5변형, 정상:결함 ≈ 1:5
- **best layer**: 메탈 L7 / 필통·하리보 L5 / 젤리껌 L8, 최종 L12 제외
- **정직성**: layer staged(bank 아직 L8, 가드 차단), 합성 도메인 갭, 수치는 base·합성·LOO·단일 seed라 실물 재검증 대상

## 8. 정직한 한계와 발표 시 방어논리

### 8.1 왜 한계를 먼저 말하는가

이 시스템에는 7가지 알려진 한계가 있다. 숨기면 청중이 찾아내고, 먼저 말하면 청중이 신뢰한다. 핵심 프레임:

> **이 한계들은 "버그"가 아니라 "검증 단계와 가드로 관리되는, 지도 위 현재 위치"다.**

안전벨트를 맨 운전자에게 "왜 사고 대비를 하느냐"고 묻지 않는다. `enabled:false`와 layer 가드가 그 안전벨트다 — "검증 안 된 건 운영에 안 올린다"는 규율의 증거다. rigid 클래스(metal AUROC 0.998/0.999, pencil 0.986/0.996)는 이미 강한 결과를 보였고, 약한 부분은 전부 **"아직 안 한 것"이지 "해봤는데 안 되는 것"이 아니다.**

### 8.2 7가지 한계 — 각각이 왜 치명적이지 않은가

| # | 한계 | 정직한 사실 | 왜 관리된 경계인가 |
|---|---|---|---|
| 1 | **Laplacian 채널 미검증** | 합성 결함이 RGB만 바꾸고 normal map은 안 건드려(Zivid PLY 조작 필요) fusion 기하 신호 TPR 기여를 오프라인 검증 불가 | 그래서 일부러 `enabled:false`. 미검증 채널을 운영에 안 올리는 게 규율 |
| 2 | **mango 운영 비활성** | mango detector가 `enabled:false`로 꺼짐 | 미완성 아닌 **의도적 안전장치**. 코드 완성, 실물 찢김 테스트(1~2봉지) 후 전환 |
| 3 | **detector 미배선** | `pick_n_place.py`에 통합 코드 없음. `src/defect/` import는 오프라인 평가 `scripts/`뿐 | detector 서브시스템 **자체는 완성**(ABC·3전략·registry·logger 동작). 배선은 후속 작업 |
| 4 | **layer staged** | config는 best layer(metal L7, pencil/haribo L5)지만 운영 bank는 L8 | layer 가드가 불일치를 **시끄럽게 ValueError로 차단**. silent 오류 방지 = 좋은 설계 |
| 5 | **fusion lap_mu/sigma placeholder** | `lap_mu=0, lap_sigma=1`로 FPR 캘리브 미실시 | 정상 데이터로 캘리브 가능하나 아직 안 함. `enabled:false`로 보호됨 |
| 6 | **합성 결함 도메인 갭** | scratch/tear 합성이 실제 결함 분포를 완전 대표 못 함(RGB만 변경) | 임계 튜닝용 proxy로 충분히 유용. 실물 재검증이 명시적 다음 단계 |
| 7 | **소형 결함 스케일 희석** | 큰 객체에서 작은 결함이 224 resize로 희석 | 알려진 trade-off. crop 448/타일링이 후속 개선안으로 정의됨 |

### 8.3 각 한계를 떠받치는 메커니즘

**`enabled:false`는 두 단계 게이트다.** registry는 (a) yaml 최상위 `enabled:false`면 전체 kill-switch, (b) per-class `enabled:false`(mango)면 그 클래스만 스킵. mango를 끄는 건 "구현이 없어서"가 아니라 "검증 통과 전까지 라우팅에서 제외"하는 명시적 결정이다.

**layer 가드는 '조용한 거짓말'을 막는다.** bank의 `dinov2_layer` 메타와 config의 `dinov2_layer`가 다르면 즉시 ValueError. 가드가 없다면 L7 config로 L8 bank를 조회해 거리가 무의미해진 채 그럴듯한 숫자를 뱉을 것이다 — 그게 진짜 위험이다. **에러로 멈추는 건 silent 오류보다 안전하다.**

### 8.4 수치의 검증 경계 — 어디까지 믿어야 하나

모든 AUROC·운영점 숫자에 4중 조건이 붙는다.

> **base 모델 · 합성 결함 · LOO · 단일 seed(=42)**

- **base**: dinov2-base(12 block). large 전환 시 layer는 상대 깊이 이동(예측 ×2), 재-ablation 필요.
- **합성**: 결함 분포가 scratch/tear 합성이라 실물과 갭.
- **LOO**: 정상은 leave-one-out, 클래스당 max_obj=80 무작위 subsample(80 초과 클래스는 부분표본값).
- **단일 seed**: seed=42 하나, 분산 미측정.
- **정상:결함 ≈ 1:5 불균형**, 지표는 표준 F1이 아니라 balanced TPR/specificity τ.

**가장 정직하게 짚어야 할 어긋남(metal):** 운영점에 적힌 metal TPR 100% / FPR 4%는 사실 **L8@τ=8.93 측정값**인데 config 채택 layer는 L7(SEPARATED, FPR≈1%)이다 → 재빌드 후 L7 기준 재측정 필요. 또 mango 0.704→0.880은 **PatchCore(max) 단독값**이지 fusion 효과가 아니다.

### 8.5 이렇게 답하세요

> **Q. 실물 결함으로 테스트는 했나요?**
> "아직입니다. 현재 수치는 전부 합성 결함(scratch/tear) 기반이고, 실물 재검증이 명시적 다음 단계입니다. 그래서 미검증 채널은 운영에 올리지 않았습니다."

> **Q. AUROC 0.99 같은 숫자를 그대로 믿어도 되나요?**
> "조건부입니다 — base 모델·합성 결함·LOO·단일 seed 기준이에요. rigid 클래스는 강한 신호지만, 이 숫자들은 실물 재검증 대상으로 명시해 두었습니다."

> **Q. mango가 꺼져 있으면 미완성 아닌가요?**
> "코드는 완성돼 있고 의도적으로 끈 겁니다. Laplacian 기하 채널을 합성으로 검증할 수 없어서, 실물 찢김 테스트 후 전환하도록 `enabled:false`로 막아뒀습니다."

> **Q. layer를 바꿨는데 안 돌면 망한 거 아닌가요?**
> "가드가 일부러 막는 겁니다. test와 bank의 layer가 다르면 거리가 무의미해지는데, 그걸 조용히 통과시키지 않고 에러로 세웁니다. silent 오류보다 훨씬 안전한 설계입니다."

> **Q. 그래서 지금 당장 현장 투입 가능한가요?**
> "rigid 클래스(metal·pencil)는 강한 결과를 냈습니다. 남은 건 pick_n_place 배선과 실물 검증 두 단계이고, 둘 다 '해봤는데 안 되는 것'이 아니라 '아직 안 한 것'입니다."

### 8.6 한 문장 요약 (각인용)

7가지 한계는 전부 **"안 해봤다"이지 "해봤는데 실패했다"가 아니다.** `enabled:false`와 layer 가드는 버그가 아니라 안전벨트이고, "단일 seed·합성 결함"은 결론이 아니라 지도 위 현위치 표시다.

## 부록. 청중 예상 Q&A 종합

### A. 왜 이 부록이 필요한가

Q&A는 청중이 **고른 한 점을 콕 찌르는** 시간이다. 까다로운 질문은 무한히 다양하지 않고 **세 갈래로 수렴**한다.

1. **"왜 이 전략을 골랐나?"** → 답은 항상 *물성과 정상 변동성(CV)*.
2. **"이거 AND 아니야? 신호 다 맞아야 결함이야?"** → 아니다, *다수결(≥2)*.
3. **"이 숫자 믿어도 되나?"** → *조건부*(base·합성·LOO·단일 seed).

세 문에 미리 자물쇠(자동응답)를 걸어두면 들어오려는 질문의 절반이 그 앞에서 막힌다. 나머지 디테일은 "그 정확한 값은 스펙 문서 §X 표 기준으로 확인해 답하겠다"로 받으면 된다 — 거짓 추측보다 항상 강하다.

### B. 핵심 3종 자동응답 (무조건 외운다)

**1) "왜 이 전략을 골랐나?" → 물성·CV가 detector를 정한다**

> "전략은 물성과 정상 변동성(CV)으로 정합니다. rigid(metal·pencil)는 단일 신호 PatchCore, deformable인 하리보는 정상 구겨짐을 거르려고 4신호 다수결, 젤리껌은 CV 0.126으로 타이트해 PatchCore 주신호 + 기하 보조 융합입니다. 근거는 스펙 §4와 §6 라우팅 표입니다."

**2) "이거 AND야?" → 아니다, 다수결(≥2 of 4)**

```
votes = 𝟙[s1>8.6] + 𝟙[s2>0.10] + 𝟙[s3>0.05] + 𝟙[s4>1.8]
is_defect = votes ≥ 2
```

> "AND가 아니라 다수결입니다. 4신호 중 임계를 넘는 게 2개 이상이면 결함이고요. 정상 구겨짐은 1표라 통과, 찢김은 여러 신호가 동시에 떠서 2표 이상이 됩니다. 코드 주석에 'AND'로 적힌 건 오기입니다. `score=max(s1..s4)`는 로깅용이고 판정은 전적으로 votes입니다."

**3) "이 숫자 믿어도 되나?" → 조건부다 (정직하게)**

> "수치는 base 모델·합성 결함·LOO·단일 seed 조건의 값이라 실물 재검증 대상입니다. 특히 합성 결함은 RGB만 바꿔서 기하(Laplacian) 신호 효과는 오프라인으론 검증이 안 되고, 그래서 mango는 `enabled:false`로 막아뒀습니다. mango 0.704→0.880도 PatchCore 단독값이지 fusion 효과가 아닙니다. 정확한 값은 §6 표와 §7 캘리브 기준으로 확인해 답하겠습니다."

### C. 보조 방어선 (덜 빈번하지만 날카로운 질문)

| 질문 | 한 줄 방어 | 근거 |
|---|---|---|
| **한 문장으로 이게 뭔가?** | 분류된 객체 단위로 정상만 학습해 표면 결함을 잡는 normal-only 이상탐지입니다. | §1 |
| **지도학습 CNN 결함탐지와 뭐가 다른가?** | 결함 라벨이 불필요합니다. 정상 patch로 memory bank를 만들고 거기서 벗어나면 결함이라, 본 적 없는 새 결함 유형도 잡습니다. | §1 |
| **`confidence`가 클래스 확률 아닌가?** | 아닙니다. 승자 클래스 이웃의 softmax 가중합이라 클래스 합이 1이 안 될 수 있어요. "확률"로 부르면 오류입니다. | §4.5 |
| **DINOv2를 학습시켰나?** | 아니요. freeze된 사전학습 ViT에서 feature만 뽑습니다. 분류·결함이 같은 backbone 공유. | §3.2 |
| **분류·결함 신호가 왜 안 겹치나?** | 보는 깊이가 다릅니다. 분류=최종 layer(카테고리), 결함=중간 layer(표면). 최종 층은 정상/긁힘을 한 단어로 부르고 중간 층은 긁힘을 튀게 합니다. | §3.1 |
| **가장 강한/약한 클래스는?** | metal_case·pencil_case가 강합니다(AUROC 0.998·0.986대). mango가 약하고 검증대기라 off 상태입니다. | §3.5, §6 |
| **지금 실제로 쓸 수 있나?** | detector 알고리즘은 오프라인 검증됐지만 `pick_n_place.py` 배선과 실물 검증이 다음 단계입니다. 아직 파이프라인에 연결돼 있지 않습니다. | §2, §8 |
| **layer가 config랑 bank랑 다르던데?** | 의도된 staged 상태입니다. config는 best layer(metal L7, 하리보·필통 L5)인데 운영 bank는 아직 L8이라, 재빌드+재튜닝 전까지 가드가 로드를 막습니다. | §3.5, §7.5 |
| **`action`으로 파지 우선순위 낮추는 거 동작해?** | 설계는 됐지만 미배선입니다. 현재 정렬 key가 `action`을 소비하는 코드는 없습니다. 솔직히 가정법 단계입니다. | §2.3 |
| **bottle은 왜 뺐나?** | 투명해서 빛이 투과하면 mask 안에 뒤 객체 patch가 섞입니다. 비교 기준인 정상 분포가 오염되므로 뺐습니다. | §5.6 |
| **하리보·젤리껌 둘 다 봉지인데 왜 다른가?** | 정상 분포가 다릅니다. mango는 CV 0.126으로 rigid급이라 4신호 다수결이 과하고, 다색이라 color 신호도 약해 단일신호+기하보조 fusion입니다. | §5.5 |
| **w=0.25는 어떻게 정했나?** | 최적화 값이 아니라 prior입니다. "찢기면 기하가 튄다"는 사전지식으로 잠정 부여했고 실물로 검증·조정 예정입니다. | §6.3 |

### D. 모르는 질문을 받았을 때의 표준 응답

세부 수치(정확한 τ, σ, layer별 AUROC 소수점)를 즉답 못 하는 건 약점이 아니다. **거짓 추측이 약점**이다.

> "정확한 값은 스펙 문서 §X 표 기준으로 확인해 답하겠습니다."
> - 정확한 수치/운영점 → **§6 클래스별 표**
> - 임계·캘리브 절차 → **§7 (LOO ROC, balanced TPR/specificity τ)**
> - layer ablation → **§7.4 / §3.5 표**

추가로, "F1-best로 튜닝했다"는 정확히는 **balanced TPR/specificity τ**다(ROC만으로는 precision을 못 구하므로). "F1이면 precision 기반 아니냐"고 찌르면 "정확히는 TPR과 specificity의 조화평균 기준이고, F1 표기는 편의상입니다"로 받으면 된다.

### E. 한 줄 요약 (각인용)

**전략은 물성·CV가 정하고(§5,§6), Cascade는 AND가 아니라 다수결 ≥2이며(§6.2), 숫자는 base·합성·LOO·단일seed 조건부라 실물 재검증 대상이다(§7,§8). 모르면 "§X 표 기준으로 확인해 답하겠다" — 검증 경계를 먼저 인정하는 게 가장 강한 방어다.**
